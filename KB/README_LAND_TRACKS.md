# Обучающие треки на демо площадки

Кнопка «обучающие треки» на `_pad_demo.py` (http://127.0.0.1:8767) показывает **что
именно видит модель при обучении**. До этого на странице было видно только то, как
модель планирует; не было видно, чему она учится.

Модуль `numeric_land/tracks.py`, эндпоинт `POST /api/track`, контроль
`python _check_numeric_land_tracks.py`.

## Три вида

| Вид | Что показывает |
|---|---|
| `window` | **окно обучения** — 4 состояния, 3 случайных действия (ровно то, что уходит в предиктор); плюс полёт-источник пунктиром |
| `flight` | **полёт-источник** — все 450 случайных действий, откуда окно вырезано |
| `expert` | **траектория правила** — полная посадка по правилу (см. `README_LAND_EXPERT.md`) |

## Почему это не «запись треков»

Записывать ничего не нужно: генерация полностью детерминирована сидом.
`window_of(seed, g)` из одного числа даёт те же состояния и действия, что уходят в
обучение. Вьюер пересобирает их на месте — ноль новых данных, и расхождение с
реальным обучением невозможно по построению.

## Что видно (сид 100000)

| | шагов | высота | покрыто высоты | доля падения |
|---|---|---|---|---|
| окно | 3 (0.1 с) | 36.76 → 36.19 | **0.57** | **1.55 %** |
| полёт-источник | 450 | 36.76 → 289.47 (вверх) | −252.71 | — |
| траектория правила | 90 (3 с) | 36.76 → 0 | 36.76 | **100 %** |

Три наблюдения, которые объясняют нулевые результаты замеров:

1. **Окно покрывает доли единицы высоты.** 0.57 из 36.76 — полтора процента падения.
   По такому окну не видно ни подвода к земле, ни касания. Бывает и отрицательное
   покрытие (сид 100001: −0.21) — модель учится на наборе высоты.
2. **Полёт-источник не садится, а улетает вверх.** На случайных действиях аппарат
   уходит выше точки старта на 252 единицы. Обучающий корпус — это данные не о
   посадке, а о том, как аппарат уходит от земли.
3. **Старт всегда у самой земли** (высота 27–37 из 512), при этом окно обрывается,
   не дойдя до касания. Модель не видит переход «над площадкой → касание».

Вместе с тем траектория правила покрывает те же 36.76 единиц целиком и садится
мягко. Поэтому в обучение экспертное семейство (`lande_*`) и добавляло такие окна —
но, как показал замер, мягких посадок это не дало (см. `README_LAND_EXPERT.md`).

## Устройство ответа

`POST /api/track {"kind": "window|flight|expert", "seed": <int>}` →

```json
{"kind": "window", "seed": 100000,
 "track":   {"n_states": 4, "n_actions": 3, "duration_s": 0.1,
             "height_from": 36.76, "height_to": 36.19, "height_covered": 0.57,
             "touched": false, "result": "не сел", "points": [...]},
 "context": { ...полёт-источник или null... }}
```

Точка — `{x, y, vy, fuel, grounded, action}`; `action` только у начала перехода.
Вид `window` дополнительно отдаёт `context` (полёт-источник), чтобы окно читалось
на фоне целого падения.

## Как смотреть

Левое полотно — общая картина в той же рамке, что у симулятора (поле 512, земля
внизу, площадка зелёным). Правое — увеличение участка трека с подписями «ш0, ш1, …»
и стрелками действий. Ниже — числа: покрыто высоты, доля падения, результат.

Для `flight` и `expert` на общей картине метка выхода за кадр: полёт уходит вверх
за пределы видимого поля.

## Воспроизведение

```bash
python _check_numeric_land_tracks.py
python _pad_demo.py            # http://127.0.0.1:8767 → секция «Обучающие треки»
```

## Запуск

Рабочие чекпоинты v0.3 — с суффиксом `v4`. Пустой `--tag` у `train.py` пишет
`out/jepa.pt` и `out/pixel.pt`: это архив эксперимента v0.2, его легко затереть.

```bash
python train.py --mode jepa  --steps 2500 --tag v4   # 5.8 мин
python train.py --mode pixel --steps 2500 --tag v4   # 15.6 мин
python probe.py --tag v4                             # ~20 с
python chat.py --tag v4
python demo_ui.py          # страница http://127.0.0.1:8765
```

Один эпизод и оценка, которой снята таблица в `README.md`:

```bash
python plan.py --goal "в центр" --cost latent
python plan.py --goal "справа снизу" --cost mixed --probe-weight 1.0

# 9 зон × 10 стартов = 90 эпизодов, не больше 20 реальных шагов
python eval.py --tag v4 --cost latent --zones 0,1,2,3,4,5,6,7,8 --seeds 10 --steps 20
python eval.py --tag v4 --cost mixed  --zones 0,1,2,3,4,5,6,7,8 --seeds 10 --steps 20
```

Дефолт `eval.py` другой: зоны `0,2,4,6,8` (пять штук), `--seeds 4`, `--steps 20`.
Команда только с `--seeds 10` даёт 50 эпизодов, не 90. Дефолт `--steps` у `plan.py` — 30,
у `eval.py` и `chat.py` — 20. Успех 82% / 73% в README снят при потолке 20:
все неуспешные эпизоды в `out/eval_v4_*.json` закончились ровно на 20-м шаге.

`imagine.py` — раскатка эксперимента v0.2. Текущие физика и предиктор другие,
повторный запуск перезаписывает `out/rollout.png` и `out/metrics.json`.
Числа того эксперимента уже лежат в этих файлах. См. [README_ARCH.md](README_ARCH.md).

### Параметры `train.py`

| Флаг | Дефолт | Смысл |
|------|--------|-------|
| `--mode` | обязателен | `jepa` (лосс в латенте) или `pixel` (лосс по кадрам) |
| `--steps` | 2500 | шагов оптимизации |
| `--batch` | 32 | батч эпизодов, данные генерируются на лету |
| `--lr` | 3e-4 | OneCycleLR, `pct_start=0.1` |
| `--seed` | 0 | сид данных и инициализации |
| `--tag` | пусто | суффикс чекпоинта. `v4` → `out/jepa_v4.pt`. Пусто → `out/jepa.pt` |
| `--unit-norm` | 1 | 1: латент на единичной сфере |
| `--threads` | 8 | см. ниже |

Горизонт обучения зашит: `HORIZON = 6` в `train.py`. В лосс идут три шага раскатки
по своим предсказаниям (`x0..x4`, действия `a1..a3`).

### Планирование, голова, оценка

| Флаг | Где | Дефолт | Смысл |
|------|-----|--------|-------|
| `--tag` | `probe`, `plan`, `eval`, `chat` | `v4` | `out/jepa_<tag>.pt`, `out/pixel_<tag>.pt`, `out/probe_<tag>.pt` |
| `--cost` | `plan.py`, `eval.py` | `latent` | `latent` или `mixed` |

| `--steps` | `eval.py`, `chat.py` | 20 | тот же смысл, другой дефолт |
| `--samples` / `--iters` | `plan`, `eval`, `chat` | 128 / 8 | CEM |
| `--zones` | `eval.py` | `0,2,4,6,8` | какие зоны; для таблицы README нужны все `0..8` |

| `--seed` | `plan.py`, `chat.py` | 1 | сид стартового состояния мира |

Формула `mixed` в коде (`plan.cem_plan`):
`probe_weight · mean(dx², dy²) / 100` при `probe_weight = 1` это `‖Δxy‖² / 200`.

## Производительность на CPU (замерено на v4)

| Что | Время |
|-----|-------|
| 1 шаг обучения `jepa`, batch 32, `--threads 8` | ~140 мс |
| 1 шаг обучения `pixel`, batch 32, `--threads 8` | ~375 мс |
| 2500 шагов `jepa` (`out/train_v4.log`) | 5.8 мин |
| 2500 шагов `pixel` | 15.6 мин |
| `probe.py` | ~20 с |
| одно решение планировщика, CEM 128×8, H=10, режим `latent` | **70 мс** медиана, p90 **85 мс** |
| то же, режим `mixed` | 71 мс, p90 84 мс |
| пиксельный CEM, 2 эпизода в `out/eval_v4.json` | **8.5 с** на решение |
| `eval.py` на 90 эпизодов | ~1 мин |
| Инференс готового I-JEPA ViT-H/16 (632M, 448×448), для сравнения | ~7.8 с / картинку |
| Инференс V-JEPA2 ViT-L (326M), 16 кадров 256×256 | ~22.8 с / клип |

Раскатка v0.2 (`imagine.py`, 30 шагов × 2 модели и картинки) занимала ~15–20 с
на физике того эксперимента.

### Почему `--threads 8`, а не 12

На 6 физических ядрах 12 потоков torch дают ~640 мс/шаг против ~210 мс при 8
(переподписка потоков на HyperThreading). Если меняете машину — замерьте:

```bash
for T in 6 8 12; do echo "threads=$T"; python -c "
import torch, time
torch.set_num_threads($T)
a=torch.randn(32,1,64,64); m=torch.nn.Conv2d(1,32,4,2,1)
for _ in range(3): m(a)
t=time.perf_counter()
for _ in range(20): m(a).sum().backward()
print(f'{(time.perf_counter()-t)/20*1000:.0f} ms')"; done
```

## Эксперименты

### Поменять физику мяча (`data.py`)

Чекпоинты `v4` обучены на этих значениях. Смена константы делает их недействительными.

| Константа | Дефолт | Эффект |
|-----------|--------|--------|
| `GRAVITY` | 0.15 | 0.0 — нет притяжения вниз. В архиве v0.2 было 0.40 |
| `IMPULSE` | 4.0 | сила действия. Меньше — предиктору снова выгодно игнорировать действие |
| `VEL_DECAY` | 0.6 | доля старой скорости. При `actions=None` (раскатка `imagine.py`) не применяется |
| `RADIUS` | 5.0 | размер мяча и отступ отскока |
| `SIGMA` | 2.8 | мягкость пятна. Меньше — острее, труднее для пиксельной модели |
| `SIZE` | 64 | разрешение кадра. 128 заметно медленнее |

Начальная скорость в `simulate` — равномерно 0.3–1.0 px/кадр.

### Что стоит попробовать дальше

**Как получить настоящее размытие у пиксельной модели.** В архивном прогоне v0.2 его
не было: мир детерминированный и полностью наблюдаемый, см. «Раскатка v0.2»
в [README_ARCH.md](README_ARCH.md). Нужна неоднозначность будущего:

- **Окклюзия**: мяч на несколько кадров перекрывается вертикальной полосой.
- **Два мяча** с разными скоростями.
- **Шум наблюдений** на входе при раскатке (`x + σ·randn`), σ ≈ 0.1.
- **Текстура на мяче** (шахматка внутри пятна).

Ещё одно, чего в лоссе нет: учить декодер отдельно, уже на замороженных латентах.
Тогда лосс энкодера станет предсказанием в латенте без реконструкции.

Действия и три шага раскатки в лоссе уже сделаны. Это v0.3, не следующий эксперимент.

## Отладка

| Симптом | Причина / что делать |
|---------|----------------------|
| Лосс предсказания растёт, `rec` падает, норма латента — сотни | масштаб уехал. Нужен `--unit-norm 1`. Поднимать `variance_term` некуда: в лосс он не входит |
| Декодированные предсказания — серый туман | энкодер потерял позицию мяча: поднять вес `rec` в `build_loss` |
| Планировщик блуждает, смена действия почти не меняет `ẑ` | предиктор игнорирует действие. Геометрия `(dx,dy)`, `VEL_DECAY` и предсказание приращения — [README_PLAN.md](README_PLAN.md) |
| Обучение идёт дольше ~25 мин на обе модели | проверьте `--threads` |
| `plan.py` / `chat.py` не находят чекпоинт | нужен `--tag v4` и файлы `out/jepa_v4.pt`, для `mixed` ещё `out/probe_v4.pt` |
| Картинки плана пустые | чекпоинт должен быть после полного прогона, не оборванный лог |

# Почему мягких посадок мало: причина найдена

Вопрос был поставлен так: «в обучающих треках почти нет мягких посадок — если нет
правильных решений, чему они научат? В чём причина: не хватает тяги? Тогда ввести
параметр».

Ответ: **тяги хватает с запасом.** Дело в другом, и это видно по числам.

## 1. Тяга ни при чём

`MAX_THRUST = 20`, а тяжесть учится на `[2, 15)`. Запас есть при любой обученной
тяжести:

| g | запас тяги (тяга − g) | тормозить умеет | g в обучении |
|---|---|---|---|
| 2 | 18 | да | да |
| 8 | 12 | да | да |
| 15 | 5 | да | нет (край) |
| 20 | **0** | **нет** — тяга ровно равна тяжести | нет |

Замер правила: `vy` в момент касания **4.5** при пороге мягкости 8 — то есть
**тормозить правило умеет идеально**. Оно стабильно садится медленно. Значит,
провал не в вертикали.

При g = 20 запас нулевой: тормозить нечем, аппарат не может даже висеть. Это и
есть единственный случай, где «параметр системы» имел бы смысл. Но он вне
обучения.

## 2. Настоящая причина: боковая скорость

Правило промахивалось по x, потому что **урезало боковую скорость**:

| | значение |
|---|---|
| цель ограничивала боковую скорость | 8 ед/шаг |
| старт стоит в | x ≈ 256 |
| площадка стоит в | 156…356 (до 100 единиц в стороне) |
| за время падения так можно пройти | **~20 единиц** |
| физический предел за то же время | ~19 единиц |
| **но бак даёт висеть** | **сколько угодно (расход 0 при frac < 0.5)** |

Вот где был спрятан рычаг: **бак тратится только при доле тяги ≥ 0.5**. Чтобы
висеть при g ≤ 15, нужна доля ≤ 0.5 — то есть **висение бесплатно**. А раз можно
висеть, можно ехать боком сколько нужно.

## 3. Правило с фазой наведения

Две фазы (`numeric_land/expert_hover.py`):

- **наведение**: держим высоту, едем боком к центру со скоростью
  «приехать и остановиться» — `v = √(2·a·d)`, потолок 40 ед/шаг;
- **посадка**: по x близко, спуск с торможением к целевой скорости.

Замер на сидах 200000…200029:

| g | прежнее правило | с наведением | шагов |
|---|---|---|---|
| 2 | мягко 9/30, промах 40 | **мягко 30/30**, промах 0.7 | 292 |
| 8 | мягко 5/30, промах 40 | **мягко 30/30**, промах 0.7 | 206 |
| 15 | мягко 5/30, промах 39 | **мягко 30/30**, промах 0.7 | 207 |
| 20 | мягко 7/30, промах 13 | на площадке 30/30, **мягко 20/30** | 360 |

Ключевая тонкость: первая версия наведения ограничивала скорость 14 ед/шаг и не
укладывалась в потолок 450 шагов — аппарат доезжал до центра, но зависал. Потолок
скорости задаёт сама физика шага: за шаг x меняется на `vx/30`, поэтому `vx ≤ 40`
даёт ход ~1.35 единицы за шаг и не перескакивает цель.

## 5. Что это меняет для обучения

Это прямой ответ на исходный вопрос. В обучающих данных не было правильных решений
не потому, что «не хватало тяги», а потому, что:

1. окно обучения (3 шага у земли) **не содержит ни подвода, ни касания** —
   см. `README_LAND_TRACKS.md`;
2. траектории, которые туда подмешивали (`lande_*`), шли по правилу v1, а оно
   **само не попадает в центр** (5/30) — то есть «правильные решения» были
   неправильными;
3. теперь есть правило, которое садится мягко и в центр **30/30** — годный
   учитель. Из него можно брать окна у земли (`hover_pool`) для дообучения
   предиктора.

## Context

`step_state` делает кадр так: `v ← 0.6·v + импульс`, затем `v_y += 0.15`, затем `x ← x + v`. Скорость здесь в пикселях за кадр. Множитель `0.6` применяется один раз на кадр, поэтому при другом `dt` доля затухания другая. Импульс `4` px за кадр тоже не ускорение. Чекпоинты `out/numeric_jepa_s*.pt` выучены на этом шаге. Сравнивать их с моделью, которая видит `dt`, значит смешать смену физики и новый канал.

Формула ТЗ другая: `v ← v + a·dt + g·dt`, затем `x ← x + v·dt`. Обновлённая скорость входит в шаг положения. Это полунеявный Эйлер. Явный вариант `x ← x + v_старая·dt` из покоя за один толчок не сдвигает мяч и этой спекой не используется.

Латент 32 шире пяти чисел. Утверждение работы — переход выучен, формулы в сеть не вписаны. Утверждение «латент сжал состояние» здесь ложно и в заметку не попадает.

`dt` внутри окна, если его менять каждый шаг, попадает в цель EMA на следующем шаге. Предиктор видит только латент и действие. Будущий `dt` из них не следует, и лосс штрафует сеть за часы. Поэтому `dt` постоянен на окне и может различаться только между окнами. На руке B окна одного батча не делят один `dt`.

Прямой L1 до EMA по-прежнему обнуляется, если все состояния кодируются одной точкой. Штраф тот же, что у числовой JEPA: сфера и пол `0.1` на стандартное отклонение.

Планирование и страница этого мира не входят в изменение. Пока нет раскатки по времени, CEM только размножит непроверенный переход. Страница продолжает показывать `numeric_jepa_s0.pt`, это другой мир.

## Goals / Non-Goals

**Goals:**

- Считать траектории новым интегратором со скоростью в пикселях в секунду.
- Выучить две JEPA на одних и тех же траекториях: состояние с `dt` и состояние без `dt`, где скорость записана в пикселях за шаг.
- Снять руку A и руку B. Проверить перенос на другой `dt` по физическому времени.
- Оставить `step_state`, эталон плоского кадра, пакет `numeric/` и страницу проверки нетронутыми.

**Non-Goals:**

- Вызов или правка `step_state`. Подгонка нового мира под пиксель в пиксель к старому кадру.
- Затухание `0.6` на кадр и непрерывное трение. Трение, если оно понадобится, — отдельное изменение.
- Загрузка `out/numeric_jepa_*.pt` или `out/numeric_direct_*.pt` как базовой линии.
- Прямой предиктор состояния, декодер, CEM, MPC, фразы, новый пункт на странице.
- Переменный `dt` внутри одного эпизода.
- Отдельный вход предиктора с `dt` рядом с латентом.
- Порог «выучил хорошо» и второй, более жёсткий порог вместо 25% среднего сдвига. Отметка «шаг не развален» — только эта доля, не оценка качества.
- Метка победителя между руками или между вариантом с `dt` и без него.
- Подбор `ACCEL`, диапазона `dt`, lr, ширины и порогов после просмотра JSON.
- Правка чисел в `KB/README_NUMERIC.md`, `KB/README_report.md` и `KB/README_report_2.md`.

## Decisions

- Код живёт в `numeric_dt/`. Пакет `numeric/` по-прежнему ходит только в `step_state`. Корневой `train.py` этот режим не получает.
- Константы кадра читаются из `data.py`: `SIZE = 64`, `RADIUS = 5`, порядок девяти действий `(dy+1)*3+(dx+1)`, `dx, dy ∈ {-1, 0, +1}`. Функция `step_state` не вызывается.
- Ускорение толчка `ACCEL = 240` px/с². Вектор действия — `(dx·ACCEL, dy·ACCEL)`. Диагональ не нормируется: длина `ACCEL·√2`, как у таблицы импульсов. Свободный полёт из покоя за секунду постоянного толчка вбок: непрерывный предел `½·a·t² = 120` px, полунеявный Эйлер при `dt = 1/30` даёт `124` px по оси толчка. На доске 64 px стенка наступает раньше. Это единицы нового мира, не подгонка под `step_state`.
- Тяжесть `g = (0, 9)` px/с². Ось `y` растёт вниз, как в лаборатории. Отношение толчка к тяжести в кадре — `IMPULSE / GRAVITY = 4 / 0.15 = 80/3`, не округлённые 27. Тогда `240 / (80/3) = 9`. Непрерывный предел за секунду без толчка — `4.5` px, толчок остаётся главным.
- Стены те же, что в `step_state`. После каждого подшага, если центр вышел из `[RADIUS, SIZE-1-RADIUS] = [5, 58]`, эта ось скорости меняет знак, положение отражается внутрь: `lo + (lo - x)` или `hi - (x - hi)`. Один проход по двум осям, как в `step_state`.
- Подшаги не длиннее 1 px, иначе `dt = 1/15` проскакивает стенку. Число подшагов `n = max(1, ceil((|v| + (|a| + |g|)·dt)·dt / 1))`. Каждый подшаг длится `dt/n` и использует ту же формулу. Действие и тяжесть на полном шаге постоянны. В записанном состоянии лежит полный `dt`, не `dt/n`. Это та же формула, не вторая физика.
- Контрольный шаг без стены, из покоя, действие «вправо» (индекс 5), `dt = 1/30`: один подшаг, `vx = 8`, `vy = 0.3`, сдвиг `(4/15, 0.01)` px. Контрольный шаг с дроблением: старт `(32, 32)`, `v = (60, 0)`, действие «на месте», `dt = 1/15`, пять подшагов, сдвиг `(4, 0.024)` px и `vy = 0.6`. Один шаг той же формулы без дробления дал бы сдвиг по `y` в `0.04` и этой спекой не принимается.
- Порядок схемы проверяется на свободном полёте, без стен. Старт `(32, 32)`, покой, действие 5, интервал `1/15` с. Точное решение `x = x₀ + ½·a·t²` даёт сдвиг `(8/15, 1/50)`. Полунеявный Эйлер при `dt = 1/60` (четыре шага, без дробления) даёт сдвиг `(2/3, 1/40)`, при `dt = 1/120` — `(3/5, 9/400)`. Обе точки впереди точного решения по обеим осям, вектор ошибки на `1/120` вдвое короче ошибки на `1/60`. Явный Эйлер, который двигает положение старой скоростью, оказывается позади точного решения. Потерянная тяжесть не попадает в `1/40` по `y`. Допуск проверки — `1e-4`.
- Старт: положение в ящике плоского мира, `RADIUS+2 … SIZE-1-RADIUS-2`. Направление равномерно по кругу. Скорость `20…60` px/с. За секунду без толчка это 20…60 px на доске 64. Не интервал `0.3…1.0` px/кадр.
- `dt` окна постоянен. Рука A пишет `1/30`. Рука B берёт один `dt` равномерно из `[1/40, 1/24]` и держит его на всех шагах этого окна. Интервал замкнут. Обучающий батч руки B собирается из окон с разными `dt`. Один `dt` на весь батч не берётся: иначе пятый канал внутри батча постоянен, и штраф схлопывания, посчитанный по батчу, не видит разброса по `dt`.
- Общий физический эпизод сида: генератор `default_rng(seed)` по порядку даёт положение, угол, скорость и индексы действий. `dt` из этого потока не берётся. У руки B обучающий `dt` берётся из `default_rng(SeedSequence([seed, 11]))`. На проверке `dt` — аргумент прогона, поток сида он не сдвигает. Поэтому сид `10000` имеет один старт и одну ленту действий на всех `dt` и на обеих руках.
- Вход сети, делители постоянные, не статистика батча.
  - Координаты делятся на 64.
  - Скорость варианта с `dt` делится на 120. Это `ACCEL·0.5` с, единица входа, не обещание, что значения лежат в `[-1, 1]`.
  - `dt` делится на `1/30`. На опорном шаге канал равен 1, на `1/60` равен 0.5, на `1/15` равен 2.
  - Скорость варианта без `dt` — это `vx·dt` в пикселях за шаг, делитель 4. Четыре пикселя за шаг равны 120 px/с при `dt = 1/30`, потому что `4 = 120·(1/30)`. На руке A после деления первые четыре канала `with-dt` и `no-dt` совпадают на любых скоростях, а пятый канал `with-dt` равен 1 и сворачивается в смещение первого слоя. Пара сетей одного сида — один класс функций, лишние 64 веса входа не несут отдельной зависимости. Любая разница их JSON — шум оптимизации. Заметка говорит это прямо и не читает «with-dt ≈ no-dt» на руке A как результат про канал. Менять делитель, чтобы числа разошлись, нельзя: при постоянном `dt` другой делитель остаётся масштабом, который первый слой впитывает в веса. На руке B та же физическая скорость при другом `dt` становится другим числом входа `no-dt`. В этом сравнение.
- Вариант `with-dt`. Состояние `(x, y, vx, vy, dt)`, скорости в px/с. Кодировщик MLP `5 → 64 → 64 → 32`, выход на единичной сфере.
- Вариант `no-dt`. Состояние `(x, y, vx·dt, vy·dt)`, канала `dt` нет. Кодировщик MLP `4 → 64 → 64 → 32`, та же сфера. Траектории те же физические, что у парного `with-dt` этой руки.
- Предиктор обоих вариантов берёт латент и `(dx, dy)` и предсказывает приращение латента. Выход на сфере. `dt` рядом с латентом не конкатенируется. Сырое состояние предиктору не подаётся.
- Цель шага — EMA-кодировщик истинного состояния, momentum `0.99`, stop-grad. Окно обучения — 6 состояний и 5 действий. Лосс — открытый L1 на первых трёх шагах, веса `1`, `0.5`, `0.25`. На вход следующего шага идёт предсказание. Первый вход — онлайн-кодировка `s_0`. Действия в окне обучения независимы на каждом шаге. Удержание `1/15` с в обучении не используется: `dt` руки B не делит этот интервал.
- Штраф схлопывания тот же: по кодировкам истинных состояний, не по предсказаниям, среднее по 32 координатам от `relu(0.1 - std)^2`, вес `0.1`. Внутри корня дисперсии слагаемое `1e-8`, чтобы градиент существовал при нулевом разбросе. Дисперсия — `unbiased=False`.
- Оба варианта, обе руки: AdamW, lr `1e-3`, weight decay `1e-4`, 3000 шагов, batch 128. Сиды обучения 0, 1 и 2. Двенадцать файлов, перечисленных в proposal. Единственный принимаемый тег — `numeric-dt`. Пустой тег, `v4`, `v5-*` и `numeric` отклоняются до первого шага оптимизатора. На запись не открываются `out/jepa.pt`, `out/pixel.pt`, `out/jepa_v4.pt`, `out/jepa_v5-*.pt`, `out/numeric_jepa_*.pt`, `out/numeric_direct_*.pt`. Имена новых файлов тег не содержат.
- Зонд — `fit_ridge`, `lam = 1e-2`, после обучения, не внутри лосса. Вход `z = E_ema(s)`, не онлайн-кодировщик. Сбор общий на руку и вариант: сиды `20000…21023`, 1024 эпизода, 4 состояния (старт и 3 шага), 4096 строк. Ridge на первых 3072, R² на последних 1024.
- Порог `0.9` стоит на целях в единицах состояния и только на этом отложенном куске.
  - `with-dt`: цели `(x, y, vx, vy)` в пикселях и px/с. Канал `dt` зонд не читает.
  - `no-dt`: цели `(x, y, vx·dt, vy·dt)` в пикселях и пикселях за шаг. На руке B физическая скорость из `vx·dt` линейно не восстанавливается, `dt` в состояние не входит. Называть это схлопыванием нельзя: представление может быть живо и при этом не содержать px/с.
- Отдельно, без порога, оба варианта получают зонд в физические `(x, y, vx, vy)`, px и px/с. У `with-dt` это тот же зонд, что и пороговый. У `no-dt` это второй ridge на тех же строках. Он учится только на распределении `dt` своей руки.
- Перенос зонда, без доучивания: те же веса, истинные состояния, R² на всех строках блока, не на предсказаниях.
  - `dt = 1/60`: сиды `22000…22255` (256 эпизодов).
  - `dt = 1/30`: сиды `23000…23255`.
  - `dt = 1/15`: сиды `24000…24255`.
  У руки A порог по-прежнему считается только по сидам `20000…21023` при `dt = 1/30`. Блок `23000` для руки A — ещё одна выборка опорного `dt`, не второй шанс порога.
- Раскатка: 64 эпизода, сиды `10000…10063`, одни и те же для двенадцати сетей и трёх `dt`. Лента — 15 индексов действий. Каждый индекс держится `1/15` с: четыре шага при `1/60`, два при `1/30`, один при `1/15`. Горизонт — 1 с, то есть 60, 30 или 15 шагов. Первый латент — онлайн-кодировка истинного `s_0`, дальше катится предиктор. Положение и скорость из латента читает замороженный физический зонд этого сида. Ошибка положения — евклидова, в пикселях. Ошибка скорости — евклидова, в px/с, у обоих вариантов. Вариант без `dt` не сравнивается в пикселях за шаг.
- Отметки времени, которые все три `dt` попадают точно. `0.5` с на сетку `1/15` не ложится, поэтому половины секунды в отчёте нет.
  - первый шаг интегратора, его длительность равна `dt`;
  - `1/3` с — шаги 20, 10 и 5;
  - `2/3` с — шаги 40, 20 и 10;
  - `1` с — шаги 60, 30 и 15.
- Рядом, без зонда, средний по 32 координатам модуль разности предсказанного латента и stop-grad `E_ema` истинного состояния на тех же четырёх отметках. Порога на этот ряд нет.
- Пол чтения, без порога. На тех же 64 эпизодах, тех же `dt` и тех же отметках замороженный физический зонд читает stop-grad `E_ema` истинного состояния, не предсказание. Пишутся евклидова ошибка положения в пикселях и евклидова ошибка скорости в px/с, среднее и выборочное отклонение. Это тот же `probe.fc`, отдельной головы нет. Если на чужом `dt` ошибка раскатки 12 px, а этот ряд 9 px, девять — чтение. Латентный ряд качественно отделяет переход от зонда и этой разности не заменяет. Зонд на `1/60` и `1/15` не доучивается: у `no-dt` вход `vx·dt` там смещён относительно отрезка `[1/40, 1/24]`, латент уходит с обученного образа, и промах чтения иначе попадает в ошибку положения.
- По каждому сиду, каждому варианту, каждой руке и каждому `dt`: среднее и выборочное стандартное отклонение по 64 эпизодам, делитель 63. Сиды не усредняются. Три `dt` не усредняются. В JSON числа с шестью знаками после запятой, сравнения порогов идут по уже записанным числам.
- Отметка «шаг не развален» ставится, только если записанная средняя ошибка положения на первом шаге строго меньше `0.25` среднего истинного евклидова сдвига на этом же `dt` и этих же 64 эпизодах. Сдвиг — среднее длин `‖p₁ − p₀‖`, не длина среднего. Порог `0.5` px снят. При старте `20` px/с и толчке вбок один шаг `1/60` сдвигает мяч на `0.4` px, и модель, которая оставляет точку на месте, прошла бы абсолютные `0.5` px. Относительный порог отличает такую модель от шага при любом `dt`: у неподвижного чтения ошибка равна самому сдвигу. Порог `1` px от числовой JEPA здесь не используется. Второго, более жёсткого порога после просмотра чисел нет. Ни JSON, ни `KB/README_DT.md` не называют отметку хорошим обучением. В JSON рядом пишется сам средний сдвиг, чтобы сравнение было видно.
- Столбец первого шага стоит на физическом времени, равном `dt`: `1/60`, `1/30` или `1/15`. Эти три числа между собой не сравниваются. Сравнимы отметки `1/3` с, `2/3` с и `1` с. Заметка говорит это одной фразой. Отметка «шаг не развален» считается внутри своего `dt` и этот запрет не отменяет.
- Для каждого `dt` записывается, больше ли средняя ошибка положения на `1` с, чем на первом шаге. Это факт, не успех и не провал.
- Любой из четырёх пороговых R² ниже `0.9` даёт метку «схлопнулось». Раскатка такого сида в JSON есть и успехом не называется. Поля успеха нет.
- Сиды обучения `0, 1, 2`, раскатка `10000…10063`, зонд `20000…21023` и три блока переноса не пересекаются. Обучение не собирает эпизоды этими сидами. Его генератор инициализируется сидом обучения.
- Пол варианта `no-dt` на руке B объявлен до прогона и порогом не является. Состояние `(x, y, vx·dt, vy·dt)` при переменном `dt` не задаёт следующий шаг: член `v·dt` входом определён, член `a·dt²` — нет. При `dt`, равномерном на `[1/40, 1/24]`, у `a·dt²` такие среднее и стандартное отклонение за шаг: толчок вбок `0.272` и `0.077` px на ось, диагональ `0.385` и `0.109` px, тяжесть `0.010` и `0.003` px. Внутри отрезка варианты обязаны быть почти вплотную, масштаб щели — десятая пикселя за шаг. Близкие числа на `dt = 1/30` не читаются как «канал dt не нужен». Щель может накопиться к секунде и может быть видна в латентном ряду. Главное различение — `1/60` и `1/15`, за краями отрезка.
- Эти края — экстраполяция, и заметка называет их так. `1/60 = 0.5 × (1/30)`, `1/15 = 2 × (1/30)`. От краёв руки B: `(1/60) / (1/40) = 2/3`, `(1/15) / (1/24) = 1.6`. Слова «не выучил зависимость» для этих чисел не используются. `dt = 1/30` на руке B лежит внутри отрезка, это не экстраполяция.
- Контрфактический шаг, только `with-dt`, каждый сид, обе руки, без порога. Физическое состояние одно: положение `(32, 32)`, скорость `(20, 0)` px/с, действие «на месте», индекс 4. Две сборки: `dt = 1/30` и `dt = 1/60`. Обе короче 1 px, подшагов нет. Интегратор сдвигает на `(2/3, 0.01)` и `(1/3, 0.0025)`. Отношение по `x` равно 2 — это член `v·dt`. Отношение по `y` равно 4 — это член `g·dt²`. Один общий множитель «1:2» на весь вектор ложен. Модель: онлайн-кодировка сборки, один шаг предиктора, положение из замороженного физического зонда. Сдвиг модели — это показание зонда минус истинное положение `(32, 32)`. Рядом пишется показание зонда на `E_ema` истинной сборки, чтобы смещение зонда было видно. Отношения компонент `сдвиг(1/30) / сдвиг(1/60)` пишутся как есть; если модуль знаменателя меньше `1e-6`, отношение — пусто. Для руки B масштаб канала `0.5` лежит вне `[0.75, 1.25]`, поэтому шаг — экстраполяция канала, не длинная раскатка. У `no-dt` канала, который можно сменить при той же физической скорости, нет, и запись ему не заводится.
- `KB/README_DT.md` говорит: переход выучен без формул; латент 32 — не сжатие пяти чисел; на руке A входы после масштабирования совпадают, пара — один класс функций, разница — шум оптимизации; пол `no-dt` на руке B равен объявленным `0.272±0.077` px за шаг толчка, близкие числа на `1/30` не значат «канал не нужен»; числа на `1/60` и `1/15` — экстраполяция `0.5×`/`2×` и `2/3`/`1.6` от краёв, не отказ учить зависимость; столбец первого шага между `dt` не сравнивается; ошибка положения включает ряд чтения зонда; старые `numeric_jepa_*.pt` — другая физика и не базовая линия; отметка первого шага — не качество; победителя нет. Числа только из `out/numeric_dt_rollout.json`.

## Risks / Trade-offs

- [Рука A выбрасывает постоянный `dt`] → на этой руке выбрасывать нечего: после масштабирования входы `with-dt` и `no-dt` совпадают, пятый канал равен 1. Заметка называет пару одним классом функций. Живая проверка канала — рука B и контрфактический шаг. Разницу шести сетей руки A результатом не называют.
- [Рука B, вариант без `dt`, плохо читает px/с] → порог `0.9` стоит на пикселях за шаг. Физический зонд пишется рядом без порога. Это ожидаемое чтение, не повод менять цели.
- [Ошибка положения на чужом `dt` — вина зонда, а не перехода] → латентный L1 считается до зонда и порога не имеет. Ряд чтения на истинных `E_ema` тех же 64 эпизодов даёт пол в пикселях. Заметка вычитает его из ошибки положения словами, не новым порогом.
- [Подшаги меняют формулу на крупном `dt`] → подшаг — та же формула на `dt/n`. Контрольный сдвиг `(4, 0.024)` против одного шага `(4, 0.04)` фиксирует, что дробление реально.
- [За секунду толчка мяч бьётся о стену] → стенка общая для всех `dt`. Укорачивать горизонт, чтобы убрать удары, эта спека не позволяет.
- [Кто-то сравнит JSON с `numeric_jepa_s0.pt`] → в заметке прямо сказано, что там пиксели за кадр и множитель `0.6`. В этот JSON старые чекпоинты не входят.
- [Порог `0.5` px прочитают как качество и он пропускает неподвижную модель на коротком шаге] → порог снят. Отметка «шаг не развален» — меньше 25% среднего истинного сдвига на этом `dt`. Второго порога нет.
- [Близкие кривые на `dt = 1/30` прочитают как «канал не нужен»] → до прогона записан пол `0.077` px за шаг. Заметка отсылает к нему. Различение назначено на `1/60` и `1/15` и названо экстраполяцией.
- [Столбец первого шага сравнивают между `dt`] → в заметке написано, что это разные физические времена. Сравнимые отметки — `1/3` с, `2/3` с и `1` с.
- [Один `dt` на батч прячет руку B от штрафа схлопывания] → `dt` свой у каждого окна. Проверка смотрит, что в батче 128 больше одного `dt`.
- [Один сид решает сравнением шум] → три сида, среднее и выборочное отклонение по эпизодам, без усреднения сидов и без метки победителя.

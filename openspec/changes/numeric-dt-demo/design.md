## Context

Страница на `http://127.0.0.1:8765` уже выбирает `pixel` и `numeric`. Числовой пункт грузит `out/numeric_jepa_s0.pt` и толкает мяч через `step_state`: пиксели за кадр и множитель `0.6`. Изменение `numeric-dt` задаёт другой интегратор и явно не добавляет пункт на страницу. Этот показ — отдельное изменение. Он не заменяет раскатку и не выбирает победителя рук.

Потолок страницы — 20 шагов и горизонт 10, поиск `128×8`. Шестьдесят перепланирований на `dt = 1/60`, если мерить одну секунду, держат кнопку десятки секунд. Поэтому потолок остаётся 20 кадров выбранного `dt`, а отчёт называет физическую длительность. Сравнивать число шагов при разных `dt` как одну секунду нельзя.

Рука A после масштабирования совпадает с вариантом без `dt`. На страницу она не годится: глаз прочитает одинаковый фильм как свойство канала. Живой пункт — рука B, вариант с `dt`, сид 0.

## Goals / Non-Goals

**Goals:**

- Дать на странице прогон с интегратором `v ← v + (a + g)·dt`, `x ← x + v·dt` и выбором `dt` из трёх значений.
- Рисовать мяч, зону, путь и направление толчка так же, как соседние пункты.
- Не сдвинуть ответы `pixel` и `numeric`.

**Non-Goals:**

- Двенадцать чекпоинтов, `out/numeric_dt_rollout.json` и `KB/README_DT.md`.
- Вариант `no-dt`, сиды 1 и 2, рука A, прямой предиктор.
- Порог успеха и слова «замер».
- Ползунок произвольного `dt`. Только три строки, которые уже есть в протоколе раскатки.
- Потолок в одну физическую секунду.

## Decisions

- Код шага живёт в `numeric_dt/` и совпадает с `numeric-dt`: `ACCEL = 240`, тяжесть `(0, 9)`, подшаги не длиннее 1 px, стены `[5, 58]`, без множителя `0.6`, без вызова `step_state`.
- Чекпоинт страницы — `out/numeric_dtB_jepa_s0.pt`. Обучение этого файла: рука B, состояние `(x, y, vx, vy, dt)`, кодировщик `5→64→64→32`, предиктор только от латента и `(dx, dy)`, AdamW, lr `1e-3`, weight decay `1e-4`, 3000 шагов, batch 128, сид 0, тег `numeric-dt`. У окна свой `dt` из `[1/40, 1/24]`.
- Зонд для стоимости учится при первом прогоне на истинных состояниях сидов `20000…21023` руки B, `lam = 1e-2`, вход `E_ema(s)`, цели `(x, y, vx, vy)` в пикселях и px/с. В лосс сети он не входит.
- Старт прогона: `default_rng(seed)` даёт положение в ящике плоского мира, угол и скорость `20…60` px/с. `dt` — аргумент страницы и этот поток не сдвигает. Скорость `0.3…1.0` px/кадр не используется.
- Кадры рисует плоский `World.frame` после подстановки положения. `World.step` не вызывается. Первый кадр — старт, второй — действие «на месте», дальше до 20 действий планировщика. Так стрелки совпадают с соседним числовым пунктом.
- CEM `128×8`, горизонт 10, элита 16, первое действие, затем план заново. Генератор поиска каждый раз сидируется сидом прогона. Стоимость: квадрат расстояния положения зонда до центра зоны, последний шаг плюс `0.3` среднего трёх последних. Успех — центр мяча в зоне.
- Выбор `dt` на странице: строки `1/60`, `1/30`, `1/15`. Нет поля — `1/30`. Иное значение — отказ 400 до плана. Пиксельный и числовой пункты поле `dt` не читают.
- Мир не `flat` при `model = numeric-dt` — отказ 400 до плана. Текст говорит, что эта модель не ведёт пиксельные миры. Ползунки холмов на шаг не влияют.
- Подпись: пять чисел, не кадр; стрелка — направление толчка, не путь за `dt`. Заметка пункта: рука B, сид 0, новый интегратор, не замер. Отчёт содержит «сид обучения 0», «рука B», «зонда», выбранную дробь `dt`. Для `1/60` и `1/15` в отчёте есть «экстраполяция». Нижняя сноска пункта говорит, что потолок — 20 шагов выбранного `dt`, не одна секунда.
- Нет файла чекпоинта — отказ с командой `python -m numeric_dt.train --tag numeric-dt`. Чужие чекпоинты на запись не открываются.

## Risks / Trade-offs

- [Двадцать кадров `1/60` короче двадцати кадров `1/15`] → отчёт пишет дробь `dt`. Сноска запрещает читать потолок как одну секунду.
- [Зонд на чужом `dt` врёт в стоимости] → для `1/60` и `1/15` отчёт говорит «экстраполяция». Это показ, не таблица раскатки.
- [Руку A выложат на страницу как сравнение] → пункт один, файл один: `numeric_dtB_jepa_s0.pt`.
- [Кадр нарисует `step_state`] → проверка интегратора обязана отличить шаг без толчка при `dt = 1/30` от `step_state`.

## Migration Plan

Новые файлы и правка `demo_ui.py`. Откат — удалить пункт, `numeric_dt/` и `out/numeric_dtB_jepa_s0.pt`. Пиксельные чекпоинты и `numeric_jepa` не мигрируют.
